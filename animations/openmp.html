How it works: #pragma omp parallel for collapse(2) splits the (y, x) loop across threads. With 4 threads, four cells get updated simultaneously each tick. Because OpenMP's scheduler dynamically distributes loop iterations, we cannot say in advance "thread 0 always does this row" — the animation reflects that by spawning the four thread colors at random positions. At the end of each timestep an implicit barrier waits until every thread is done before the time loop advances.
